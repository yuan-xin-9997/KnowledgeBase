# 阅读、目录、同步与恢复

## 目录和阅读

- 目录默认按层级按需加载；单层每次 200 项，可继续加载。目录区域只渲染可见行。全部展开时一次读取该来源已收录目录，再按可见区域渲染。
- 目录数量包含子目录文档。当前目录以路径导航显示，可逐级返回；目录折叠只影响显示。
- 展开状态、上次选择的文档及页码、阅读位置保存在当前浏览器，按登录用户隔离。清理浏览器数据会清除这些状态。
- 文章大纲可跳到尚未载入的 Markdown 标题；正文继续按需载入。搜索词在正文中高亮并定位到命中位置。
- 图片可点击放大、缩放和重试。图片失败时显示服务端原因；外部图片受原站权限和防盗链限制，系统无法保证失效外链可恢复。

## 重复文档

- 对至少 80 字符的正文进行 Unicode 规范化和空白归一后计算 SHA-256；这识别相同正文，不进行语义相似判定。
- 列表显示相同正文数量，阅读页可查看对应副本；勾选「折叠重复正文」后按当前筛选结果保留一份代表文档，统计和分页使用相同规则。
- 不自动合并、删除或修改信息源文件；AI 检索会避免同一正文反复占用上下文。

## 文件夹问答与引用

- 当前目录下可点击「对当前文件夹及子目录提问」。阅读助手也提供当前文件夹范围。
- 完整会话的指定来源范围支持可选文件夹路径；清空该字段恢复整个来源范围。
- 文件夹约束覆盖标题命中、全文检索与宽松检索。引用链接携带实际检索片段，打开后定位原文；若原文更新导致片段失效，页面明确提示。

## 同步明细与失败项重试

- 信息来源 → 记录 → 查看项目明细，可按新增、更新、跳过、移出索引、失败筛选，分页显示项目路径及失败原因。
- 「仅重试失败项」仍需扫描来源以定位项目，但只重新加载失败项，不清理其他资料，也不推进来源的完整同步时间。
- 失败项目已从来源消失时会保留失败明细，提示检查来源或执行完整同步。旧版本的任务没有逐项明细，下一次同步开始记录。

## 应用备份与恢复

设置页面中管理员可查看应用备份、最近操作结果，创建和验证备份。此功能独立于 Jenkins 的部署前归档。

备份位于 `DATA_DIR/backups/backup-<UUID>/`：

- `knowledge.db`：SQLite 在线 Backup API 的一致性快照。
- `secret.key`：实际使用的加密主密钥，包括通过 APP_SECRET 提供的密钥。
- `manifest.json`：创建时间、数据库及密钥的 SHA-256。
- `verification.json`：最近一次独立恢复验证结果。

每次创建后自动复制到独立临时目录，检查数据库完整性、外键关联，以及来源和模型配置能否被备份密钥解密。验证不会覆盖运行中的系统。备份包含全部用户的数据，仅管理员有访问权限；请按私密数据保管。系统不自动删除备份，请管理员定期转存和清理应用备份目录。

### 恢复到新目录

构建服务后运行：

```sh
node scripts/restore-backup.mjs /path/to/data/backups/backup-UUID /path/to/new-restored-data
```

目标目录必须不存在。脚本先验证备份，再复制和复验；拒绝覆盖任何已有目录，包括现有数据目录。

校验成功后：

1. 停止服务，并保留原 DATA_DIR 以供回退。
2. 将部署配置的 DATA_DIR 指向恢复目录。沿用 HOST、PORT、APP_ORIGIN 等环境配置；若配置 APP_SECRET，必须与备份中的 secret.key 完全一致，或移除 APP_SECRET 让系统读取该文件。
3. 以服务运行账号启动服务，检查 `/api/health`、登录、来源和文档。
4. 验证失败时停服，将 DATA_DIR 切回原目录，然后重新启动。

备份不包含原始信息源、SMB 附件缓存和浏览器阅读状态。原始来源始终只读；SMB 原件需全量重新同步以重建缓存。来源文件丢失无法靠系统备份恢复。
